# PIPELINE — idea to publication

**Read `README.md` first for what the three strands are. This file is the how.**

## Rule zero: the pipeline is a COST, and only one strand pays it

| Strand | Runs stages | Stops at |
|---|---|---|
| **learning/** | 0 → 11 | Published |
| **yuba/** | 0 → 6, then case-by-case | Depends who it's for |
| **personal/** | 0 → 6. **That's it.** | Sent |

**A song for your wife or for your son does not need a lyric video, a thumbnail,
or a grade audit.** It needs to be good and it needs to arrive. If a song for
your family has to clear eleven stages, you will never send one — and that is
the actual risk to this strand, not quality. Write it, generate it, listen once,
send it.

---

## Stage 0 · Decide the strand
Different audience, different privacy, different success test. Get this wrong and
every later stage is wrong. `personal/` is **private and never published** — that
is a standing rule, not a per-song decision.

## Stage 1 · Write — THREE lyric documents, not two
The two-document rule became three the moment the lyric videos got a spec.

| File | For | Rules |
|---|---|---|
| `learner.txt` | study | Correct orthography + romaji + gloss. Kanji fine — it's a page, you can stare at it. |
| `suno.txt` | the machine | Phonetic. `は`→`ワ`, `を`→`オ`, ambiguous kanji→katakana, digits spelled out. See `findings.md` F-02. |
| `screen.txt` | **the video** | Correct orthography, **no romaji, no furigana, no gloss**, kanji held to the song's grade. **The strictest of the three** — read in real time with zero support. |

`screen.txt` is new and it is the one that decides whether the video teaches.
Everything a learner cannot decode in the second it is on screen is wasted.

## Stage 2 · Lint before you spend a generation
```
python3 tools/kanji_grade.py learning/01-aisatsu/screen.txt --grade 1
```
Reports every kanji, its grade, and whether the song clears the target. Also
prints the fixed kanji panel for the video, so that list is **generated, not
hand-kept**. Grades 2–6 are empty stubs on purpose — see the script's docstring.

Also re-run the F-08 adjacency check: no two adjacent lines may differ by a single
word or mora, or Suno will collapse them into one.

## Stage 3 · Generate — one pass
Persona (see `house-style.md`) + style prompt + `suno.txt`. **One pass.** Do not
split and merge — that is retracted, `findings.md` F-09. Tempo 85–100.

## Stage 4 · Audit — read along, every time
**The only detector for dropped lines is your eyes on `screen.txt` while it plays.**
Do it on the first listen, before deciding whether you like the take — a missing
line is easy to miss when you are listening for whether the music is good.
This is stage 4 and not stage 8 because everything downstream is wasted on a bad take.

## Stage 5 · Repair — paid
Mid-song pronunciation fixes need a paid plan (confirmed 2026-08-27). This is now
a **validated** reason to subscribe rather than a speculative one: without it, one
bad syllable costs a whole regeneration and a new set of random defects.

## Stage 6 · Assemble audio
Sting + song + sign-off. The sting and sign-off are **standalone assets in
`assets/`, generated once and edited on** — not regenerated per song. That is what
makes them a signature instead of a coincidence. See `house-style.md`.

**→ personal/ ends here. Send it.**

## Stage 7 · Timing
Word-level timing JSON. This file — not the video — is the pipeline's real
artifact: it decouples *when each word is sung* from *how the video looks*, so
you can rebuild the video a hundred times without re-timing.

**Do it by hand for song one.** Forty lines, twenty minutes in any audio editor.
Automate only after the format has proven itself — the F-09 lesson is: do not
engineer around a problem you have not measured. When you do automate, this is
**forced alignment, not transcription** (you already know the text), which is a
much easier problem. WhisperX gives word-level timestamps; Montreal Forced Aligner
is reportedly more accurate for exactly this case.

## Stage 8 · Video
**Remotion** — React, programmatic, renders MP4, word-level caption libraries
already exist. Right tool because the series needs the *same* video a dozen times
with different content, which is what a template engine is for and what a
timeline editor is bad at. Suno does not do video.

The spec, from Nepô 2026-08-27:
- Words highlight as sung, Japanese only, no romaji, no furigana
- Kanji held to grade — panel fixed on screen, generated by `tools/kanji_grade.py`
- Timecodes · waveform · elements pulsing to the beat

**And the visuals come from the Irasutoya catalogue.** 36,000 illustrations
already indexed and mapped to every topic on the slate. `tools/pipeline/index/q.py`
finds the illustration for the word being sung. This is the step where the song
series stops borrowing from the encyclopedia and starts being made of it.

## Stage 9 · Thumbnail
Same source, same system: Irasutoya illustration + the song's kanji + the series
mark. Generated from a template alongside the video, never hand-made.

## Stage 10 · Publish
YouTube. Series identity is format — same sting, same sign-off, same thumbnail
grammar, same title pattern.

## Stage 11 · Log
Append to `findings.md`, whether it worked or not. **Every entry in that file cost
a generation to learn.** Include the full recipe: persona, model version, style
text, what was excluded, what changed, what happened.

## Implementation map — the stages as real commands

The template exists now, and each stage below is a concrete command. Folder layout,
naming, and the single-source-of-truth model are documented in `PROJECT-STRUCTURE.md`.
`<id>` is the slug, e.g. `01-aiueo`.

| Stage | Command(s) | Notes |
|---|---|---|
| 0 Strand | (read `learning/<id>/song.json` → `strand`) | `personal/` stops after stage 6. |
| 1 Write | author `learner.txt`, `screen.txt`, `suno-*.txt` by hand | the three-document rule above. |
| 2 Lint | `python3 tools/kanji_grade.py learning/<id>/screen.txt --grade N` | + the F-08 adjacency check; + slug-only path check. |
| 3 Generate | (Suno, external) → take into `learning/<id>/Songs/` | one pass (F-09). |
| 4 Audit | read `screen.txt` along with the take | eyes on every line — the only dropped-line detector. |
| 5 Repair | (Suno paid, external) | mid-song pronunciation fixes. |
| 6 Assemble | choose take → `learning/<id>/audio/master.wav` | sting + song + sign-off. **personal/ ends here.** |
| 7 Timing | `node tools/build_learning_timing.mjs <id>` → `python3 tools/align/align_song.py <id>` → (opt.) `npm --prefix video run nudge` | scaffold → forced-align → hand-tune. Merge-preserving: re-running the scaffold on an aligned song only refreshes the header. |
| 8 Video | `node tools/gen_registry.mjs` → `node tools/sync.mjs <id>` → `npm --prefix video run render -- <id>` (and `<id>-vertical`) | outputs to `video/out/<id>/` (canonical, overwrite). |
| 9 Thumbnail | `npm --prefix video run still -- <id> …` + `tools/kanji_grade.py` panel | → `video/out/<id>/<id>-thumb.png`. |
| 10 Publish | `node tools/gen_description.mjs <id>` → paste `build/description.txt`; upload `out/<id>/` cut + `build/vocab.md` | YouTube. |
| 11 Log | append the recipe to `findings.md` | every entry cost a generation. |

Adding a song is the stage-7/8 chain with no `.tsx` edits — see
`PROJECT-STRUCTURE.md` → *Add a new song*.

## Future — a thin orchestrator (not built yet)

Today each stage is a separate manual command, which is the right amount of
structure for a handful of songs. When the slate grows, wrap the above in one
dispatcher so a stage span runs with precondition checks and logging:

```
node tools/pipeline/run.mjs <id> --stage=video      # one stage
node tools/pipeline/run.mjs <id> --from=timing --to=publish   # a span
```

`run.mjs` would only *sequence* the existing scripts (each stage shells out to the
command in the table above) — nothing gets rewritten. It would also gate by strand
(personal stops at 6) and refuse a stage whose inputs are missing (no `audio/master.wav`
before timing, no aligned timing before video). A repo-root `package.json` could then
expose `npm run pipeline -- <id> …` as the single entrypoint the project currently
lacks. Deferred deliberately: the value only appears past a few songs, and the design
is captured here so it can be built without re-deciding it.
